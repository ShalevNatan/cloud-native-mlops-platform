# Project Definition

## Project Name

Cloud-Native MLOps Platform

## Objective

Build a production-oriented cloud-native platform that demonstrates
the complete lifecycle of deploying and operating a machine learning
workload on AWS.

The platform will combine:

- Infrastructure as Code
- Cloud infrastructure
- Kubernetes
- CI/CD
- GitOps
- Observability
- Machine Learning
- MLOps

## Primary Goal

The primary goal is not to build a sophisticated machine learning model.

The primary goal is to demonstrate the ability to design, provision,
deploy, operate, monitor, and improve an ML workload running on
cloud-native infrastructure.

## Career Objective

The project should provide genuine hands-on experience that can be
confidently discussed in DevOps, SRE, Platform Engineering, Cloud,
and MLOps interviews.

Every major component should be understood by the developer rather
than treated as a black box generated by AI.

## Core Engineering Principles

1. Understand before implementing.
2. Prefer simple production-like solutions over unnecessary complexity.
3. Every major technology must have a clear purpose.
4. Infrastructure and application lifecycles should be separated.
5. Security and cost should be considered from the beginning.
6. Failures and troubleshooting are part of the learning process.
7. The final system should be explainable end-to-end.

## Initial Technology Direction

- Cloud: AWS
- Kubernetes: Amazon EKS
- Infrastructure as Code: Terraform
- Containers: Docker
- Container Registry: Amazon ECR
- CI: GitHub Actions
- GitOps/CD: ArgoCD
- ML: Python / scikit-learn
- MLOps: MLflow
- Metrics: Prometheus
- Visualization: Grafana

These choices are initial decisions and may be changed only after
documenting the reasoning.

## Scope

The project will initially focus on:

- AWS infrastructure
- Kubernetes platform
- Application deployment
- CI/CD
- GitOps
- Observability
- ML training and inference
- Model lifecycle management
- Kubernetes scaling
- ML-assisted workload prediction

## Non-Goals

The project will not attempt to:

- build a sophisticated research-grade ML model
- use GPU infrastructure unless there is a demonstrated need
- introduce technologies solely to increase the technology count
- reproduce a large enterprise architecture unnecessarily
- hide implementation complexity behind AI-generated code
